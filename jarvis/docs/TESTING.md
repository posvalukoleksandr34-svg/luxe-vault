# J. Тестирование

## Уровни

| Уровень | Что проверяет | Где | Как запустить |
|---|---|---|---|
| Unit | роутер моделей, параметры API, политика разрешений, исполнитель инструментов, крипто, SSRF, парсер времени | `backend/tests/test_llm.py`, `test_policy_executor.py`, `test_security.py` | `make test-backend` |
| Integration (реальные Postgres+pgvector и Redis) | агентный цикл, одобрения и возобновление, отмена, идемпотентность после падения, taint, суб-агенты, память (гибридный поиск, дедупликация, извлечение, деградация без эмбеддингов), очередь и планировщик, каналы (Telegram/WhatsApp с подписью), API и авторизация | `test_harness.py`, `test_memory.py`, `test_tasks_scheduler.py`, `test_channels.py`, `test_api.py` | `make test-infra && make test-backend` |
| Навыки | каждый навык со своими тестами, внешние HTTP подменены `httpx.MockTransport` | `skills/*/tests/` | входят в `make test-backend` |
| Сценарии | пять сценариев из ТЗ через весь конвейер: HTTP API → беседа → очередь → агент → инструменты → БД → ответ | `test_scenarios.py` | входят в `make test-backend` |
| Frontend | типы (`tsc -b`), компоненты (Vitest + Testing Library), сборка | `frontend/src/test/` | `make test-frontend` |
| E2E в браузере | Playwright против развёрнутого `docker compose`: вход, чат, одобрения, задачи, аудит | вручную, см. ниже | — |

Integration-тесты помечены `@pytest.mark.integration` и **автоматически пропускаются**, если тестовая БД
недоступна. Адреса: `JARVIS_TEST_DATABASE_URL` (по умолчанию
`postgresql+asyncpg://jarvis:jarvis@localhost:55432/jarvis_test`) и `JARVIS_TEST_REDIS_URL`
(`redis://localhost:56379/15`). Тесты очищают эту тестовую БД — не направляйте их на рабочую.

## Сценарии из ТЗ

Сценарии гоняются с **DemoBrain** — детерминированной заменой модели на правилах. Так проверяется вся
механика (разрешения, долговечность, память, расписания, доставка), но не «ум» модели.

| # | Запрос | Что проверяется |
|---|---|---|
| 1 | «Запланируй встречу с Анной завтра в 15:00» | агент сначала смотрит календарь (конфликты), затем создаёт событие в часовом поясе пользователя; событие в БД |
| 2 | «Найди информацию о … и сделай отчёт» | без настоящего мозга агент честно говорит, что не может искать, а не выдумывает отчёт |
| 3 | «Напиши письмо … и покажи перед отправкой» | создаётся черновик, текст показан, **ничего не отправлено**; отправка — отдельный confirm |
| 4 | «Каждую пятницу в 18:00 присылай обзор недели» | `automation_create` требует подтверждения → задача ждёт → после «Подтвердить» автоматизация создана с верным cron и следующим запуском |
| 5 | «Запомни, что мне нравится джаз» → «Что мне нравится?» | запись в долговременную память и извлечение гибридным поиском |
| + | «Напомни через 30 минут позвонить в банк» | создаётся напоминание с верным временем и текстом (срабатывание и доставку проверяют `test_tasks_scheduler.py` и E2E ниже) |

## Ручная проверка с настоящей моделью

После настройки ключа Anthropic пройдите в чате (и повторите 1–2 пункта в Telegram и голосом):

1. «Запланируй встречу с Анной завтра в 15:00» → ответ с временем; событие на Dashboard (блок календаря) и в Google Calendar, если подключён.
2. «Найди свежие новости о Claude и сделай короткий отчёт с источниками» → статусы «Ищу в интернете…»,
   отчёт со ссылками; для длинной работы — фоновая задача и уведомление по завершении.
3. «Напиши письмо Ивану о переносе встречи и покажи перед отправкой» → черновик в чате;
   «отправляй» → карточка «Я готов выполнить действие. Подтвердить?».
4. «Каждую пятницу в 18:00 присылай мне обзор недели» → подтверждение → запись в «Автоматизациях»;
   кнопка «Запустить сейчас» на той же странице — проверка без ожидания пятницы.
5. «Запомни: мой любимый кофе — флэт уайт» → новая беседа/другой канал → «Какой кофе я люблю?».
6. «Стоп» во время длинного ответа → задача отменена.
7. Журналы → Аудит → «Проверить целостность» → «Цепочка цела ✓».

## Проверено при разработке

Результаты последних прогонов в среде разработки:

* backend + навыки: **100 passed** на реальных Postgres 16 + pgvector и Redis 7; frontend: `tsc -b`,
  Vitest 5/5, `vite build` — зелёные;
* `docker compose` (api, worker, caddy, postgres, redis, browser, sandbox) через Caddy, Playwright:
  вход; сценарии 5, 1, 4 с одобрением из UI; напоминание, поставленное **до** `docker compose restart api worker`,
  сработало после перезапуска; страница задач; проверка аудит-цепочки; нет ошибок в консоли при строгом CSP;
* песочница: uid 20001, read-only FS, нет DNS/интернета, нет доступа к Postgres;
* удалённый браузер (Playwright server) работает из воркера;
* бэкап: образ собирается, `make backup` создаёт снимок restic, `restic check` — без ошибок.

Что **не** проверено автоматически — см. [STATUS.md](STATUS.md#что-не-проверено).

## CI

Workflow в репозиторий пока не добавлен (см. ROADMAP, этап 2). Рекомендуемый конвейер (GitHub Actions): сервисы `pgvector/pgvector:pg16` и `redis:7`, затем
`make test-backend` с `JARVIS_TEST_DATABASE_URL`/`JARVIS_TEST_REDIS_URL` на эти сервисы и
`make test-frontend`. Интеграционные тесты не требуют ключей и внешней сети: модель — DemoBrain/скрипты,
HTTP — моки, эмбеддинги — `hash`.
