# E. Дорожная карта

## Этап 0 — сделано (эта версия)

Ядро и всё, что нужно для ежедневного использования одним человеком на своём сервере: durable-агент,
роутер моделей, разрешения с одобрениями во всех каналах, долговременная память, навыки, MCP,
задачи/напоминания/автоматизации, web/голос/Telegram/WhatsApp, аудит, бэкапы, мониторинг, спутник
с wake word. Подробно — [STATUS.md](STATUS.md).

## Этап 1 — первая неделя после установки (ваши действия)

1. Ключ Anthropic → ручной прогон сценариев из [TESTING.md](TESTING.md).
2. Домен + HTTPS, TOTP, off-site репозиторий бэкапов, **пробное восстановление** на отдельной машине.
3. Telegram-бот (5 минут), затем Google (Calendar + Gmail).
4. Заполнить `config/identity/user.md`; через неделю — просмотреть «Память», удалить лишнее, закрепить важное.
5. Подобрать `effort` в `config/models.yaml` по ощущению скорости и траты на Dashboard.

## Этап 2 — качество и скорость (1–2 недели разработки)

* **Потоковое STT** (Deepgram live WebSocket): частичные транскрипты, ответ начинается раньше; цель — первый
  звук < 1.2 с после конца фразы.
* **Оценки (evals)** на реальных диалогах: набор из 30–50 запросов с ожидаемыми вызовами инструментов,
  прогон при каждой смене модели/промпта.
* **Сводки длинных бесед** и компактизация контекста для многочасовых задач.
* Привязка `trace_id` к каждой строке логов (structlog contextvars) и OpenTelemetry-трейсы.
* CI в GitHub Actions (backend с Postgres/Redis, frontend, сборка образов).

## Этап 3 — охват (по потребности)

* Microsoft 365 (Outlook, Calendar, OneDrive) через Graph API — по образцу `integrations/google/`.
* IMAP/SMTP и CalDAV — для не-Google почты и календарей.
* WhatsApp-шаблоны для уведомлений вне 24-часового окна.
* Web push и PWA (установка на телефон, уведомления без Telegram).
* Wake word в браузере (openWakeWord через onnxruntime-web) для режима «кухонный планшет».
* Home Assistant как готовый навык (сейчас — через REST-коннектор или MCP).

## Этап 4 — автономность (осторожно)

* Агент на настольном ПК (управление окнами/приложениями) — отдельный процесс с собственным токеном
  устройства, все действия — confirm, запись экрана в аудит.
* Проактивность: утренний брифинг, «вы просили напомнить о…», мониторинг писем от важных людей —
  как автоматизации, которые пользователь включает явно.
* Многопользовательский режим (семья): UI управления пользователями, общие и личные пространства памяти.

## Принципы развития

* Новая возможность = навык или MCP-сервер, а не правка ядра.
* Любое новое внешнее действие получает `Risk.EXTERNAL` и проходит через одобрение.
* Сначала тест (сценарий), потом код; в `STATUS.md` — только проверенное.
