# Безопасность

JARVIS имеет доступ к почте, календарю, файлам и может действовать от вашего имени. Поэтому модель
угроз строится от трёх рисков: **чужой человек получает доступ**, **чужой контент управляет агентом**
(prompt injection через письмо или сайт), **сам агент ошибается**.

## Модель угроз и ответы

| Угроза | Защита |
|---|---|
| Подбор пароля | argon2id; 10 попыток входа / 5 мин с IP; блокировка аккаунта на 15 мин после 8 неудач; TOTP |
| Кража сессии | cookie `HttpOnly`, `Secure` (при HTTPS), `SameSite=Lax`; список сессий с отзывом; срок `JARVIS_SESSION_TTL_DAYS` |
| CSRF | все изменяющие запросы требуют заголовок `X-Jarvis-Request` (браузер не пошлёт его с чужого сайта) + проверка Origin для WebSocket |
| XSS | строгий CSP (`script-src 'self'`, без inline-скриптов и `data:`-шрифтов), безопасный рендер Markdown без HTML, `X-Content-Type-Options`, `frame-ancestors 'none'` |
| Чужие сообщения в Telegram/WhatsApp | бот отвечает только привязанным аккаунтам; привязка одноразовым 6-значным кодом (хранится хешем, 10 мин, лимит попыток); только личные чаты в Telegram |
| Поддельные вебхуки | Telegram — секретный заголовок; WhatsApp — HMAC-SHA256 подпись тела `X-Hub-Signature-256` |
| **Prompt injection** | недоверенный вывод (веб, письма, файлы, MCP, внешние API) оборачивается в `<untrusted_content>` с инструкцией не исполнять команды из него; после попадания такого контента в задачу **все write-инструменты требуют подтверждения** (taint); отправка наружу всегда подтверждается человеком |
| Ошибочные действия агента | 4 уровня разрешений; отправка писем только через черновик + подтверждение; удаление — в корзину `.trash`; лимит шагов и дневной бюджет |
| Кража секретов из БД | ключи интеграций, OAuth-токены и TOTP-секреты шифруются Fernet (MultiFernet с ротацией); мастер-ключ — в `.env` или томе с правами 600, не в БД |
| Утечка секретов в логи | structlog-процессор маскирует ключи/токены/пароли; в аудит пишутся только очищенные аргументы |
| SSRF (агент ходит во внутреннюю сеть) | `web_fetch` и коннекторы проверяют каждый адрес и редирект: запрещены private, loopback, link-local, CGNAT, metadata, имена Docker-сервисов, URL с учётными данными |
| Выполнение кода | отдельный контейнер `sandbox`: сеть `internal` без интернета и без доступа к БД/Redis, read-only FS, uid 20001, `cap_drop: ALL`, `no-new-privileges`, лимиты CPU/RAM/PIDs, таймаут с убийством группы процессов, лимит вывода; сам инструмент требует подтверждения |
| Браузер | Playwright в своём контейнере и своей сети; к данным JARVIS доступа нет; ввод в формы требует подтверждения |
| Подмена истории | `audit_log` только на добавление (триггер БД запрещает UPDATE/DELETE), каждая запись содержит хеш предыдущей; проверка: `jarvis verify-audit` или Журналы → Аудит → «Проверить цепочку» |
| Сеть | наружу открыт только Caddy (80/443); Postgres/Redis в `internal`-сети; Grafana только на 127.0.0.1; `/metrics` закрыт на edge и требует bearer-токен |

## Уровни доступа

* **Сессия браузера** — полный доступ владельца.
* **Повышенные права** (`/api/auth/elevate`, пароль или TOTP, 10 минут) — нужны для restricted-действий,
  изменения ключей API и перевода не-read инструментов в autonomous. Отключение TOTP требует текущий код.
* **Токен устройства** (спутник, скрипты) — только перечисленные скоупы (`voice`, `chat`, …), без
  доступа к настройкам и секретам.
* **Каналы** Telegram/WhatsApp/голос могут одобрять максимум confirm-действия; restricted — только в вебе.

## Рекомендации по эксплуатации

1. Включите TOTP сразу после первого входа.
2. Держите сервер обновлённым (`unattended-upgrades`), SSH только по ключу, `ufw` с 22/80/443.
3. Сохраните `JARVIS_MASTER_KEYS` и `RESTIC_PASSWORD` вне сервера; храните бэкапы off-site (S3/B2).
4. Ротация ключа шифрования — см. [OPERATIONS.md](OPERATIONS.md#ротация-ключа-шифрования).
5. Раз в месяц: Журналы → Аудит → «Проверить цепочку»; Настройки → Сессии — отзовите лишнее.
6. Давайте MCP-серверам и коннекторам минимальные токены; оставляйте `default_risk: external`.
7. Навыки — это Python-код, выполняемый в воркере: устанавливайте только те, чей код прочитали.
